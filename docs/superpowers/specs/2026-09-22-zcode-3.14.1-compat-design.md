## 背景

ZCode 桌面端从 3.5.3 升级到 3.14.1（2026-09-20 构建）。对两个版本的 app.asar
做了静态对照，结论：App 0.1.5 依赖的全部协议与 DOM 契约保持兼容，无需协议层
改动。静态分析覆盖不到的部分（二维码/深链接生成端、运行时事件流）需要真机
联调验证。

### 静态对照结论（3.5.3 → 3.14.1）

| 契约项 | 结果 |
| --- | --- |
| Wire 信封（dataBase64 / 分片 / wireVersion） | 不变 |
| 端点 mobile-view-state(-update) | 不变 |
| 显式事件名（permission_request 等） | 不变 |
| 差分结构（session.upserted / pendingInteractionSummary） | schema 不变 |
| displayStatus 枚举 [idle,running,completed,error] | 不变 |
| DOM：data-session-id / task-item-<id> testid / 返回按钮 | 不变 |
| task.upserted（新增消息类型） | App 0.1.5 已支持 |
| 页面→服务器 zcode_type WS 消息（新增） | 不影响事件镜像方向 |

## 验证设计

分工：Agent 负责 adb 侧（安装 APK、抓取 logcat `ZCodeEvent` 日志、判读解析），
用户负责手机端操作（扫码、触发任务、查看通知）。

验证清单（按依赖顺序，每项标注 通过/失败/受限）：

1. 连接建立：adb 安装 debug APK → 添加连接 → 远程页加载出任务列表
2. 扫码/深链接链路：桌面生成二维码 → 手机扫码添加（静态分析未覆盖，重点项）
3. 四类事件通知：桌面触发 完成/失败/审批/提问，logcat 确认 TaskEventParser
   解析出事件、通知弹出、点击跳转正确
4. 会话跳转：点通知进入对应会话（data-session-id === taskId 判定成立）
5. 保活：息屏 ≥1 分钟后唤醒，会话仍在、事件不丢
6. 断线重连：桌面端重启会话后 App 自动恢复

判定标准：全通过 → 收尾；任一失败 → 回到诊断流程定点修复后回归该失败项；
模拟器环境受限项（通知点击、指纹、保活）标注"受限"。
